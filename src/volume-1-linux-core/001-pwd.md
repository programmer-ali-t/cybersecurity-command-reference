## FUNCTION

**Purpose.** Print the absolute pathname of the current working directory.

**Formal definition.** `pwd` reports the current working directory (CWD) of the invoking process. Two implementations exist: a shell builtin that consults the shell's internal `$PWD` variable, and an external `/bin/pwd` that calls `getcwd(3)`, which in turn derives the path from the process's inode chain or the kernel's dentry cache. The two can disagree in the presence of symlinks and bind mounts.

**When to use.**

- Before writing to a relative path in a script.
- Before destructive operations (`rm`, `chmod`) to confirm location.
- In reports, to record where a command was executed.
- To detect a stale shell after a directory has been moved or replaced.

**When NOT to use.**

- As a substitute for absolute paths in scripts. Prefer `cd` with absolute paths.
- To detect symlinks in the path. Use `pwd -P` explicitly.

**Preferred alternatives.**

| Situation | Better tool |
|---|---|
| Need canonical path resolving symlinks | `pwd -P` or `realpath .` |
| Need the physical path on macOS | `/bin/pwd -P` |
| Script assertions | `[ "$(pwd)" = "/expected" ]` |

**Curated options.**

| Option | Meaning |
|---|---|
| (none) | POSIX default; behavior depends on `$PWD` integrity |
| `-L` | Logical — use `$PWD` including symlinks |
| `-P` | Physical — resolve all symlinks, call `getcwd(3)` |

**Dangerous options.** None. `pwd` is non-destructive on every supported platform.

**Deprecated / changed.**

## OPERATIONAL

**Privilege required.** None.

**Failure modes.**

| Failure | Cause | Fix |
|---|---|---|
| Prints stale path after `mv` of the directory | Shell caches `$PWD` | `cd .` or use `pwd -P` |
| `pwd: error retrieving current directory` | CWD deleted | `cd /` immediately; shell cannot recover old path |
| Different output across two terminals | Each shell has its own `$PWD` | Expected; use `realpath` for a canonical answer |
| `pwd -P` on a bind-mounted directory | Prints the mount source path | Use `findmnt` to identify the bind |

**Blast radius.** None. The command is a single read.

**Recovery path.** Not applicable.

**Performance impact.** Negligible. `pwd` performs one `getcwd` syscall or a shell variable read. Under 0.1 ms.

## SECURITY

**MITRE ATT&CK.**

| Technique | ID | Relevance |
|---|---|---|
| System Location Discovery | T1614 | Direct match |

**Attacker abuse.** Attackers rarely need `pwd` explicitly because it is trivially inferred, but `pwd` appears in nearly every recon shell sequence. Forensic value is high: shell history records `pwd` invocations, revealing which directories an operator worked in.

**Detection signals.**

| Source | Signal |
|---|---|
| Shell audit (auditd execve) | Presence of `pwd` immediately before sensitive commands |
| Bash history forensics | Sequence: `whoami; id; pwd; ls -la` = classic recon pattern |
| EDR process trees | `pwd` as a child of a reverse shell |

## EDUCATIONAL

**Learning objective.** Explain the difference between logical and physical working directory, and demonstrate a case where they differ.

**Prerequisites.** Basic shell usage; concept of symlinks.

**Guided exercise (20 min).**

1. `mkdir -p /tmp/lab/pwd/src && ln -s /tmp/lab/pwd/src /tmp/lab/pwd/alias`
2. `cd /tmp/lab/pwd/alias && pwd && pwd -P`
3. Record the output. Explain in one sentence why they differ.

**Challenge (45 min).**

Reproduce a case where `pwd` prints a path that no longer resolves. Write a one-paragraph operational note about the risk in scripts.

**Quiz.**

1. What syscall does the external `/bin/pwd` use?
2. In which two cases can `pwd` and `pwd -P` differ?
3. What does the shell print when the current directory has been deleted by another process?
4. Why is `pwd` useful in a forensic timeline?

**Real-world story.**

In 2023, an incident responder documented a case where an attacker used a bind mount to hide a directory from `find` sweeps. The responder caught it only because the `pwd` in the attacker's shell history printed a path that did not appear in `find /`. Lesson: logical vs. physical paths matter.
