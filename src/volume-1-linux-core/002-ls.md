## FUNCTION

**Purpose.** List directory contents with optional metadata: names, permissions, ownership, size, timestamps.

**Formal definition.** `ls` calls `opendir(3)` and iterates `readdir(3)`, then for each entry optionally calls `lstat(2)` to retrieve metadata. Without `-l`, no stat call is made and output is names only. With `-l`, one `lstat` per entry — on network filesystems this dominates runtime.

**When to use.**

- Inventory of a directory before modifying it.
- Confirming ownership and permissions before `chmod`/`chown`.
- Building file lists in scripts (prefer `find` for robustness).

**When NOT to use.**

- Parsing output in scripts. Filenames may contain newlines, spaces, control characters. Use `find -print0` or shell globs.
- Recursive scans. Use `find` or `tree`.

**Preferred alternatives.**

| Situation | Better tool |
|---|---|
| Machine-parseable listing | `find . -maxdepth 1 -print0` |
| Tree view | `tree`, `exa`, `lsd` |
| Sortable timestamps | `ls -lt --time-style=full-iso` |
| Modern color and git status | `eza --long --git` |

## SYNTAX

**Canonical form.**

```text
ls [OPTION]... [FILE]...
```

**Curated options.**

| Option | Meaning |
|---|---|
| `-l` | Long format — permissions, links, owner, group, size, date, name |
| `-a` | Include hidden entries (`.`, `..`) |
| `-A` | Include hidden except `.` and `..` |
| `-h` | Human-readable sizes (K, M, G) |
| `-t` | Sort by modification time, newest first |
| `-S` | Sort by size, largest first |
| `-r` | Reverse sort |
| `-R` | Recurse into subdirectories |
| `-i` | Show inode numbers |
| `-n` | Numeric UID/GID |
| `-Z` | Show SELinux context |
| `--color=auto` | Color by file type |

**Dangerous options.**

| Option | Risk |
|---|---|
| `-R` on `/` or `/proc` | Can hang shell; massive output |
| `-l` on a directory with millions of files | High IO, memory spike |
| `-l` on NFS with stale mounts | Blocks indefinitely |

**Deprecated / changed.**

| Old | Current | Note |
|---|---|---|
| `ls --color` default in scripts | Use `--color=auto` | Always redirect to `cat` or disable |
| `ls -h` without `-l` | No effect | `-h` only meaningful with size output |

## APPLICATION

**Minimal example.**

```bash
ls /var/log
```

**Realistic example — recent logs with full metadata.**

```bash
ls -lht --time-style=full-iso /var/log | head -n 20
```

**Expected output.**

```text
total 2.4M
-rw-r----- 1 root adm  158K 2026-01-15 08:14:22 +0000 auth.log
-rw-r----- 1 root adm  2.1M 2026-01-15 08:14:22 +0000 syslog
-rw-r--r-- 1 root root  128K 2026-01-14 23:59:59 +0000 dpkg.log
```

**Interpretation.**

- `total 2.4M` — sum of allocated block sizes, not file sizes. Directories count as 4096 bytes each on ext4.
- Permissions block: `-rw-r-----` — type, owner rw, group r, other none.
- Link count: `1` for regular files, `>=2` for hard-linked or directory entries.
- Timestamp: modification time unless `-u` (access) or `-c` (status change).
- `+0000` — timezone offset from `--time-style=full-iso`. Crucial for correlating with logs.

**Common misreadings.**

| Misreading | Reality |
|---|---|
| `total` is total bytes | It is 1K blocks by default |
| `ls -l` size for directories | Shows directory entry size, not content |
| Sorted alphabetically by default | Sorted by locale collation; can differ across systems |
| Symlink shown with `-l` shows target size | Shows link target string length, not target size |
| `ls` reads file content | `ls -l` calls `lstat`, never `open` for read |

## OPERATIONAL

**Privilege required.** None for listing. `-Z` context display may show partial SELinux context without root. Reading directory contents requires `r` on the directory, not on files.

**Failure modes.**

| Failure | Cause | Fix |
|---|---|---|
| `ls: reading directory '.': Permission denied` | Missing `r` on directory | `sudo ls` or fix ACL |
| Output stops mid-list | Slow filesystem (NFS) | `ls -f` (unsorted, faster) |
| Colors break in pipe | `--color=auto` misconfigured | Use `--color=never` in scripts |
| Different sort order across systems | Locale collation | Set `LC_ALL=C` for deterministic |

**Blast radius.** None.

**Recovery path.** Not applicable.

**Performance impact.** `ls` on 1M files: ~2–5 s with `-l`, ~0.5 s with `-f`. `-R` on `/usr` ~ 30 s, thousands of stat calls.

## SECURITY

**MITRE ATT&CK.**

| Technique | ID | Relevance |
|---|---|---|
| File and Directory Discovery | T1083 | Direct match |
| Indicator Removal — File Deletion | T1070.004 | `ls` reveals what remains |

**Attacker abuse.** `ls -la` in `/tmp`, `/dev/shm`, `/var/tmp` is a near-universal post-exploitation step. `ls -la /root` or `ls -la /home` with elevated privilege confirms privilege. Modern attackers prefer `find` or `fd` to avoid shell history noise but `ls` remains common.

**Detection signals.**

| Source | Signal |
|---|---|
| auditd execve | `/bin/ls` or `/usr/bin/ls` invoked by non-login shell |
| shell history | `ls -la /tmp` following `whoami` |
| eBPF | `getdents64` calls in rapid succession from one PID |
| EDR | `ls` as child of `nc`, `python3 -c`, `perl -e` |

## EDUCATIONAL

**Learning objective.** Read a long-format listing accurately and explain `total`, link count, and directory sizes.

**Prerequisites.** Unix permissions, symlinks, hard links.

**Guided exercise (20 min).**

Create 3 files of different sizes, one symlink, one directory. Run `ls -lha --time-style=full-iso` and explain every column.

**Challenge (45 min).**

Build a directory with 100,000 empty files. Time `ls` vs. `ls -f` vs. `find . -maxdepth 1 | wc -l`. Explain the difference.

**Quiz.**

1. What does the `total` line mean?
2. Why does a directory show size 4096?
3. When does `ls -l` show the symlink target's size instead of the link string?
4. Why is parsing `ls` in scripts dangerous?

**Real-world story.**

A 2022 incident: an analyst grepped `ls -la` output for `.ssh` and missed the directory because the filename contained a trailing space, shifting every column by one. Lesson: parse `ls` with `--quoting-style=shell-escape` or use `find`.
